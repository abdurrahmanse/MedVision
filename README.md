# MedVision

An enterprise-grade, end-to-end educational platform demonstrating deep learning deployment. This monorepo features a PyTorch Convolutional Neural Network (CNN) wrapped in a FastAPI backend, orchestrated with a PostgreSQL database, and surfaced via a Next.js frontend.

---

## Problem
The goal of this project is to demonstrate how to bridge the gap between machine learning research and production engineering. It highlights how to take a raw PyTorch model, wrap it in a secure and scalable API, manage prediction state in a relational database, and build a modern, responsive user interface to interact with the inference engine.

## Dataset
The model was trained on the open-source **Chest X-Ray Images (Pneumonia)** dataset, originally sourced from Kaggle and Mendeley Data. It contains thousands of validated pediatric chest X-ray images, categorized into "Normal" and "Pneumonia". 
*(Note: This project is strictly educational and is NOT intended for clinical use.)*

## Architecture
This project uses a modern turborepo monorepo architecture:
- **Client ➔** Next.js 14 App Router (React, TailwindCSS, TypeScript)
- **API ➔** FastAPI (Python, Uvicorn)
- **Inference ➔** PyTorch (CPU-bound TinyCNN)
- **Data ➔** PostgreSQL (SQLAlchemy ORM)
- **Cache ➔** Redis
- **Orchestration ➔** Turborepo and Docker Compose

Data moves synchronously: 
1. The user uploads an image via the Next.js frontend.
2. The image is securely streamed to the FastAPI backend.
3. The image is resized, normalized, and converted into a PyTorch Tensor.
4. The CNN outputs a classification and a confidence score.
5. The result is persisted in PostgreSQL and returned to the client to update the UI.

## ML
- **Preprocessing:** Images are converted to grayscale, resized to `28x28`, converted to Tensors, and normalized `(mean=[0.5], std=[0.5])`.
- **Model:** A custom `TinyCNN` containing two Convolutional blocks (`Conv2d` -> `ReLU` -> `MaxPool2d`) and a linear classification head.
- **Evaluation:** Evaluated using Binary Cross Entropy (BCEWithLogitsLoss) and standard binary classification accuracy metrics. A reproducible training pipeline is available in `ml/pipeline.py`.

## API
The FastAPI backend (`apps/api`) provides the following core endpoints:
- `GET /api/v1/health`: Returns API health and readiness status.
- `GET /api/v1/model`: Returns the currently loaded PyTorch model configuration and version.
- `POST /api/v1/predictions`: Accepts a multipart/form-data image upload, runs inference, and saves the result.
- `GET /api/v1/predictions`: Retrieves the historical inference log (paginated).
- `GET /api/v1/predictions/{id}`: Retrieves a specific inference record by UUID.

## Frontend
The Next.js web application (`apps/web`) allows users to:
- Securely upload medical imagery (JPEG/PNG) via a drag-and-drop zone.
- View real-time loading states while the PyTorch model processes the image.
- Immediately view the diagnostic prediction and the model's confidence interval.
- Browse a persistent history table of all previous predictions generated by the system.

## Database
A PostgreSQL database securely stores:
- `id` (UUIDv4)
- `predicted_class` (String: "Normal" or "Pneumonia")
- `confidence` (Float: 0.0 to 1.0)
- `model_version` (String: e.g., "v1.1.0")
- `image_url` (String: Path to local storage or CDN)
- `created_at` (Timestamp)

## Run locally

**Option 1: Docker Compose (Recommended)**
```bash
# Spin up the entire enterprise stack (Postgres, Redis, FastAPI, Next.js)
docker compose up --build
```

**Option 2: Turborepo Native**
```bash
# Install dependencies
pnpm install

# Run the Next.js and FastAPI services concurrently
pnpm dev
```
*(The frontend will be available at `http://localhost:3000` and the API at `http://localhost:8000`)*

## Testing

**Backend (Pytest)**
```bash
cd apps/api
pnpm test
# Or run manually: pytest -v
```

**Frontend (Vitest)**
```bash
cd apps/web
pnpm test
```

**End-to-End (Playwright)**
```bash
cd apps/web
pnpm run e2e
```

## Limitations
- **Medical Disclaimer:** This system is built strictly for educational software engineering purposes. The `TinyCNN` model architecture is drastically downscaled for rapid compilation and is in no way fit for actual medical diagnosis.
- **Hardware Acceleration:** The current Docker setup compiles PyTorch for CPU execution to ensure cross-platform compatibility. Production deployments should modify the Dockerfile to include CUDA/MPS drivers for GPU acceleration.
